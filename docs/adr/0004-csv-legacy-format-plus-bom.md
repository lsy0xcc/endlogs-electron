# ADR-0004：CSV 以旧项目 8 列格式为标准，仅加 UTF-8 BOM

- 状态：已接受（2026-11-20）；时间列格式与文件名部分被 ADR-0009 修订（+08:00 偏移、uid 后缀）；列结构被 ADR-0013 修订（v2 十列）、时间列时区被 ADR-0012 修订（跟随系统时区）

## 决策

导出格式与旧项目 `endlogs` 完全一致（8 列、单文件单币种、`\r\n`、QUOTE*MINIMAL、文件名 `endfield*{type}_{start}_{end}.csv`），唯一变化是加 UTF-8 BOM 解决 Excel 中文乱码。导入接受带/不带 BOM 的同结构文件，按 `(account_id, currency_type, seqId)` upsert。详见 csv-format.md。

理由（旧格式足够好）：

- 8 列恰好覆盖流水库去重与重建所需的全部字段（seqId + 原始值），信息无损
- 与旧项目互通：旧用户的存档可直接导入；新导出的旧项目也能读
- 变动数量不带符号与「原因」列的展示化是可接受的瑕疵——导入时用原因码 + 最新码表重新解释，反而更新鲜

为什么不扩展（加账号 UID 列等）：

- 破坏与旧格式的往返兼容；多账号归属用「导入时选账号」这一交互解决，够用
- 真正缺的东西（币种枚举、时区标记）靠文档约定而非列扩展

## 后果

- 导出的时间列无时区标记：约定为基准时区 Asia/Shanghai（见术语表「时间处理规则」），导入按此解析
- 导出直接读流水库，不再像旧项目那样重新请求上游
