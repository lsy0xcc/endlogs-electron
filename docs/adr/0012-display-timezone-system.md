# ADR-0012：显示时区跟随系统时区

- 状态：已接受（2026-11-23，用户决策）
- 修订：术语表原「基准时区 Asia/Shanghai」规则，及 ADR-0009 中「时间列恒为 +08:00」

## 背景

原决策固定 Asia/Shanghai，理由是国服数据、与原版 endlogs 一致、CSV 往返确定性。

事实澄清：网页/游戏内显示的时间来自 API 的 `changeTime`（unix 秒，绝对时刻），页面只是按本地时区格式化显示。因此显示用哪个时区都不损失信息；CSV 时间列的显式偏移已使其自描述，往返确定性不再依赖固定时区。

## 决策

1. 「显示时区」= 用户**系统时区**：UI 展示、查询日期边界（00:00:00–23:59:59）、CSV 导出的时间列均按它计算
2. CSV 导出时间列：`YYYY-MM-DD HH:MM:SS±HH:MM`，偏移为系统时区的当前偏移
3. 原版格式（无偏移）CSV 导入：仍由用户选择时区、**默认 Asia/Shanghai**（原版 endlogs的导出口径），不因本决策改变
4. 存储与上游不变：unix 秒绝对时刻

## 后果

- 同一份数据在不同时区的机器上导出，时间列字面值不同、但带偏移后表示同一时刻；导入按偏移解析，往返无损
- 移除「基准时区」概念及「系统时区 ≠ 基准时区」的提示需求（ui.md）
- 汇总的「按日」分组边界随系统时区变化（用户视角自洽，接受）
