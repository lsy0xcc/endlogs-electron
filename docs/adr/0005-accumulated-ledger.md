# ADR-0005：流水库 = 唯一展示口径；拉取恒为全量（changeType=0）

- 状态：已接受（2026-11-20）

## 背景

两个事实：

1. 用户需求：展示基于**当前账号全部已获取流水**，而非单次拉取结果
2. 原版 endlogs 缺陷：把 `changeType`（获取/消耗）作为 API 参数做**服务端过滤**后，返回的 `after` 序列不连续，从中推导的期初/期末余额是错误的（原版 endlogs `stats/aggregate.py` 的已知问题）

## 决策

1. 本地 SQLite 流水库是**唯一**展示/导出口径；拉取与导入只是向流水库 upsert 数据的手段
2. 拉取**始终传 `changeType=0`（全量）**入库；获取/消耗过滤是**展示层**的 SQL 条件，永远不改变期初/期末的计算基础
3. 增量拉取按 seqId 早停 + upsert 幂等（见 data-model.md）——**2026-11-23 修订**：早停机制由 ADR-0015 定为「本页全部已知且最新记录 ≤ T」，upsert 幂等不变

## 后果

- 期初/期末在任意过滤视角下都正确（修复原版 endlogs 缺陷）
- 代价：想只看「获取」时也要拉全量数据。接受——三币种流水量级（页大小 50）可控，且增量同步摊薄成本
- 流水库中不存在 changeType 过滤后的「半截」数据，任何未来展示需求（图表、报告）都从同一口径出
- 隐含承诺：任何新写入路径（导入、未来的其他来源）都必须走全量语义 + seqId upsert
