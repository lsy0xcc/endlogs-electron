# ADR-0015：同步状态单列化（T）与事实边界

- 状态：已接受（2026-11-23）；同日修订：`maxLookbackDays` 在设置页为**只读展示**（自动检测值），用户不可手动修改——「用户手动修改设置」触发提示的分支作废，仅保留「检测值与上次不同」触发

## 背景

上游分页只能从最新往旧翻、无日期参数，「拉到指定深度」必然翻过其间所有数据。设计必须防住三类缺口：

1. **导入孤岛**：CSV 导入在未拉取区域形成已知数据孤岛；若早停只看「本页已知」，会停在孤岛顶端，孤岛下方可获取的数据永久缺失
2. **悬空覆盖**：新拉取段与旧覆盖之间留下可获取的洞（曾评估 W/T 双列覆盖声明方案 `settled_before` + `contiguous_until`，入口收敛后证明冗余，弃用——见下）
3. **死亡区**：旧覆盖与上游返回边界之间的区域已不可获取；若不显式处理，每次同步都白翻页

拉取入口收敛为两个按钮：「同步数据」（目标 = T，无 T 时全量）与「获取全部历史数据」（翻到 `hasNext=false`）。在此入口集下，W（`settled_before`）的全部职责蒸发：

- 拉取目标由 T 直接给出；早停化简为「本页已知且最新记录 ≤ T」——翻页从新到旧单调下降，首个满足的页必然紧贴 T 下方，孤岛/悬空已知数据（在 T 之上）天然不触发
- 缺口唯一的出生方式是拉取在 `hasNext=false` 处停在旧 T 之上，这种缺口整个位于上游边界之下，**出生即死亡**——「早于 W 已结算」不再需要存储，拉取引擎在上游尽头面前本就走不下去

「是否永久忽略死亡区」式弹框的「否」亦被证明严格无意义：两选项在任何场景下都不产生数据差异（洞在上游边界之下，除「获取全部历史数据」外无法救回，而该按钮不依赖同步状态）。

## 决策

1. `sync_state` 每账号 × 币种只存 `synced_until`（T）。不变量：**[T, 现在] 内任何上游能返回的记录都已在库**（死亡区缺口对其恒真）。拉取成功后 `T = 现在`。
2. 早停条件：**本页全部已知 且 本页最新记录 ≤ T**。
3. 缺口通知：拉取停在旧 T 之上时，缺口 (旧 T, 停点) 出生即死亡——发**非阻塞通知**（「xx–xx 的记录已无法从客服中心获取」），不设选择框。
4. `maxLookbackDays` 设置为**纯咨询**预测值（默认 90）：不限制拉取行为，仅影响进度条分母与「推荐获取全部历史数据」提示；官方游戏日志页 HTML 文案可解析出该值（暂以 TBD 异步存根恒返回 90 实现）。设置页**只读展示**检测值、不可手动修改（2026-11-23 修订）；检测值与上次不同 → 提示「推荐获取全部历史数据」。
5. 不变项：翻页途中经过的记录一律 upsert；CSV 导入永不写 `sync_state`；拉取恒传 `changeType=0`（ADR-0005）。

## 后果

- 同步状态只有一列，一切拉取后更新分支塌缩为「T = 现在」；孤岛与悬空已知数据由下次「同步数据」翻页穿越吸收
- 上游窗口宽/窄变化自愈：变宽 → 「获取全部历史数据」拉到新边界；变窄 → 自动出现死亡区通知。状态里不存任何边界（预测值不落库），常量变更无需迁移
- 代价：无 T 账号（全新/仅导入）的首次「同步数据」翻满整个上游窗口 × 3 币种，一次性成本，之后 T 建立即恢复 1 请求早停
- 「最多可获取天数」设置必须文档化为非限制性，防止未来被误解为省流量开关（见 R7）
